# Rufi: engineering rules

If something is unclear, stop and ask; don't guess. Rules are added here when the code they govern lands.

## Tests

- If code decides it, a code test covers it, with exact assertions.
- If the AI decides it, a live AI test covers it (real AI, fictional data), reported as passes out of runs. The live smoke set (`pnpm smoke`, the test sign-in in `RUFI_HOME`) runs each case three times; run it when the agent, its instructions or Rufi's tools change.
- An agent adapter passes the same contract tests as the others: `server/chat.test.ts` runs on the scripted fake Codex and on the real Codex binary against a local fake model, offline.
- No mocking the AI's judgement in code tests. No test modes in `src`: fakes are injected at the composition root.
- Every test meets the `tdd` skill's bar. Always keep: live safety tests, person scope, nothing private in logs, backup, restore and export, `schema.sql`, `tools.json`, the Codex protocol types, Stop and clean-up.
- The screens are tested in Chromium with Playwright (`apps/web/e2e/`) on the real core with the built screens, the scripted fake Codex and a fictional data folder, with axe on each screen and no CSP refusal; a short chat smoke runs the real Codex binary on the local fake model.
- The Rufi app is tested with Playwright's Electron support (`apps/desktop/e2e/`) on the real `rufi start`, a fictional data folder per test, signed out; `e2e/fakes.ts` (loaded with `-r`) stands in for the Mac's message box and the browser. No test link names a scheme the Mac itself opens (`mailto:`, a made-up one): its alert can stop Electron from starting until someone closes it. CI runs them under a virtual display. Dock, menus, focus and the looks are checked by hand on the Mac.

## Code

- **Effect v4 only; never v3 APIs** (lint refuses v3 package names). Effect for the parts that open, close, wait or fail; plain TypeScript elsewhere (ADR 0002).
- Check Codex protocol claims against `protocol/` and the `openai/codex` source at the pinned tag; most of the app-server is undocumented.
- Every external call has a deadline. Errors keep their `cause`. No empty `catch`, and a comment is not handling.
- Logs hold fixed events and checked fields only (`platform/logs.ts`): a new event or field is added there. Never prompts, replies, health text, tokens or error messages.
- Folders in `apps/server/src`: `platform` (Mac things) uses no other folder; `core` (record, tools, transcripts) and `agent` (sign-in, Codex) use only `platform`; `server` (the chat and the local API) joins `core` and `agent`; `cli` joins them all. Lint checks these borders. API shapes live in `packages/contracts` (Effect Schema).
- `apps/web` (the screens: React, TanStack Router and Query, Tailwind) uses only `@rufi/contracts` and the HTTP API; no server code and no `node:` modules (lint checks this). The core serves its build (`apps/web/dist`) on its own port. The tab's proof stays in `api.ts`; a 401 ends the session for every request.
- `apps/desktop` (the Rufi app, Electron) runs `rufi start` on the pinned Node as a child, over Node's IPC channel (`cli/app.ts`, `@rufi/contracts/app`); it imports neither the server's nor the screens' code (lint checks this) and reads no `core.json`. Its window (`src/window.ts`) sets every guard explicitly: no Node or preload, context isolation, sandbox, web security, no permission but writing text to the clipboard (Copy), no new window, no download but a file the page itself made (a blob of its own origin, such as the export), saved where the person chooses, navigation only within the core's origin (and, inside a frame, the built-in PDF viewer, which shows a document's original from a blob of the page), no redirect out, storage in memory. As in the web app, an http(s) link the page follows or opens goes to the browser (none with a name or password in it); one a frame follows doesn't (a link inside a PDF does nothing), and a popup goes only while the page has no frame, because Electron doesn't say which frame opened it (Rufi's only frame is a PDF's popup, a blob the page made: its pages refuse to be framed and its CSP allows no frame but its own blobs, but script can still make a blank or `srcdoc` frame, which takes the page's CSP). What guards this is the page's CSP: only Rufi's own code runs, and replies are Markdown without HTML. Remaining risk: script that somehow ran in the page could open an address in the browser, with data in it. Known gap: Electron doesn't report a navigation to `about:blank`, so one leaves the window blank (⌘W and the Dock bring Rufi back). It loads the screens from the loopback port, so it trusts the other programs on this Mac as the browser does. The screens see `RufiApp` in the user agent, mark the page `data-app`, and style the app on the `data-sidebar` and `data-toolbar` hooks.
- The AI's text is shown as Markdown only: no HTML, no images, and links only to http(s) pages, opened outside Rufi with no opener or referrer (`apps/web/src/transcript.tsx`).
- Every colour on the screens comes from the theme tokens in `apps/web/src/themes.css` (Tailwind's palette is off; lint refuses raw colours in `apps/web/src` and `apps/desktop/src`). A theme is one block of their values; `public/theme.js` names it on `<html data-theme>` before the page paints, from the appearance the core writes on `<html data-appearance>` (system, light or dark; the setting `appearance`), and follows a change to either. The app's windows take the Mac's appearance from the core's `x-rufi-appearance` header (`followAppearance` in `apps/desktop/src/window.ts`).
- In `apps/web`, a value that changes lives in a store, state or ref, never in a module-level `let` that components reassign: React Compiler 1.0 can read such a variable after a later reassignment.
- One process owns the data folder at a time: the core holds `rufi.lock` for its whole life, and each terminal command holds it too. Sign-in and token renewal take `credentials.lock` inside it (always `rufi.lock` first). If `rufi.lock` is lost, the core stops writing at once.
- Only the core writes the database. Rufi's tools read through their own read-only connection; `save_changes` writes through the core's, in Rufi's chat only. A transcript change is stored first and shown from what was stored (`core/chat/transcript.ts`).
- The AI reads the record only through Rufi's tools, for the person Rufi chose: no tool takes a person, a table or SQL from the AI (`get_records`, ADR 0006).
- A tool answer may carry images (a document page, as data: URLs); they are never stored: `tool_calls` keeps the text, and an activity's details leave the image out. Pages come from one page service (`core/documents/pages.ts`) for the chat's `get_documents` and the reader's `get_page`.
- Rufi's sub-agents (the document reader) run through `agent/codex/subagent.ts`: an app-server of their own, an ephemeral thread with Rufi's instructions in place of Codex's and empty developer instructions, no environment, network, sub-agents, web search, goals or skills, and exactly the tools they are given. `subagent.test.ts` proves on the pinned Codex that the model can call only those tools, also after a compaction. The runner accepts only gpt-5.5, where Codex adds none of its own, and refuses a turn when Codex's effective config at the reader's cwd or its managed requirements add instructions or tools. Any other item in the turn fails it. Never relax these settings to make a test pass.
- The reader's notebook (`core/documents/notebook.ts`) is written only by `save_page`: the page's entry and the note in one transaction, for the running job's current attempt, a target page, and a page looked at since the last compaction. Its checks only flag an entry, never change it.
- Documents are read by jobs (`core/documents/reading.ts`, run by `server/reader.ts`), one at a time, as each is added, with the model and effort chosen in Settings when a run starts (only models the sub-agent runner accepts). Only a reader turn that completed normally finishes a job, once, in one transaction with its end line (`chat.event`): page states, draft items from that job's entries, the document's version, the job done. Anything else keeps the notebook and makes no drafts (ADR 0009). Draft items are never the record: no record read sees them. A person's fix (`core/documents/items.ts`) changes a pending item's fields only, never its `original`, names the version it was made on (an older one is refused with the item as it is now), and raises the item's and the document's version.
- A reply is stored as it came; its How is split off when it is read (`core/chat/basis.ts`), and its Used is built each time from its own `tool_calls` and activity lines, never stored (ADR 0007).
- Rufi owns what waits to go to the AI: one queue per chat (`core/chat/queue.ts`), the person's messages and Rufi events' notes; the agent's own queue is never used (ADR 0004). A send moves the box's text into a row and empties the draft in one transaction, by the send's id. The dispatcher (`server/chat.ts`) claims a turn's rows in the database before it calls the agent, starts a turn only when none runs, and never hands a row over twice: an unknown hand-over is `not_sure`, never retried. Stop's pause is stored before the interrupt; only the person's send ends it.
- A Rufi event (`chat.event`) is written with its producer's outcome in one transaction: a transcript line of kind `event` and, to tell the AI, a queue row with origin Rufi. A turn started by Rufi can only read (`chatCaller` refuses saves); an event is never the person's words.
- Each person has one chat, made in the same transaction as the person (`addFirstPerson` in `core/chat/transcript.ts`); `chats.person_id` is unique; Send never creates or navigates. The chat's state has one owner each: a draft is the core's (`core/chat/drafts.ts`, the box's side in `apps/web/src/draft.ts`); the last save wins. Nothing is saved as a page closes. Chips are pointers: the core checks each against the person and stamps its version when it accepts the message, never trusting a name or version from the screen.
- The screens read the transcript by pages (`page` in `core/chat/transcript.ts`): `seq` ranges widened to whole turns, never offsets. In `apps/web/src/transcript-state.ts` a newer read always wins and a reconnect replaces what is loaded. Lines the chat derives (days, where the AI started afresh) are worked out when shown, never stored.

## Docs

- Three places: `docs/help/` for people (also the in-app help and the website, as they are), `GLOSSARY.md` for everyone, `AGENTS.md` and `docs/adr/` for developers; otherwise the `project-docs` skill.
- A change to behaviour, commands or settings updates its help page and the glossary in the same pull request; the step's plan names the pages, or says why none change.
- Use the glossary's words everywhere: screens, docs, the AI's instructions and code.

## Data model

- Person‑owned rows carry `person_id`; references between them use composite `(person_id, id)` foreign keys, so the database rejects cross‑person links. File bytes are shared and carry no person.
- A document's originals are kept as they came in `files/<sha256>`, written and synced before any row points to them (`core/documents/originals.ts`); then one transaction writes the files, the document and its pages. A document's pages point to files (a PDF page, or a whole photo); the same content belongs to at most one document per person. Files are looked at (type by content, pages, a HEIC's JPEG copy) in a worker thread with a deadline (`core/documents/inspect.ts`).
- Store values as printed and dates at the precision known; never overwrite printed fields.
- Backups and the export read one fixed copy of the database, with every original file that copy names, each checked by its hash; a backup counts only after its check, and a missing or changed original fails it (ADR 0008). Caches (`cache/`, such as a HEIC's display copy) are made again when missing and never backed up. Rufi never starts on a folder that has `installed.json` and no `rufi.sqlite`, and restore never writes over anything.
- The record changes only by a save (ADR 0005, `core/record`): one transaction with the records, each one's before and after, and the receipt built from what was stored. Records are never deleted (`removed`). A date keeps the user's words; code checks dates, sources and the health rules, never what the user meant. A saved document item's values come from the stored item, never the AI; whether it is new, another source or a correction is the AI's call with the user. Sources are typed rows in `record_sources` (a message, or a document page), several per record. There is no count limit on a save.

## Data and privacy

- **Fictional data only** in code, fixtures, tests and screenshots. Never commit real health data, tokens or keys.
- Development and tests use a fictional data folder outside the checkout.

## Git

- `main` changes only through pull requests: one small step each, checks green, review answered, then squash‑merge.
- Commit messages say what changed and why, in plain English.

## Commands

- `mise install && pnpm install`: pinned Node, pnpm and gitleaks; turns on the git hooks.
- `pnpm check`: oxfmt, oxlint (type-aware), TypeScript 7, builds the screens, then tests, unused-code check and Playwright. Green before every pull request. `pnpm format` fixes formatting. Once: `pnpm exec playwright install chromium`.
- `pnpm start [--no-open]`: builds the screens, starts the core with the real Codex and opens a single-use link; while it runs, it asks the running core for a fresh link instead (`core.json`). Ctrl-C stops it. For screen work, `pnpm --filter @rufi/web watch` rebuilds and you reload.
- `pnpm desktop`: builds the screens and opens the Rufi app, which starts the core itself or opens on the one `pnpm start` runs. ⌘W keeps Rufi running; ⌘Q and Ctrl-C stop what the app started (gracefully, killed after 10 s), then close the windows without asking the page. A killed or crashed core leaves nothing behind because Codex ends itself and its commands when its stdin closes (`contract.test.ts` checks this on the fake and the real Codex). On the Mac it runs Electron from a copy of its bundle named Rufi (`apps/desktop/node_modules/.cache`). Electron (pinned) fetches its binary on first use; it has no install script.
- `pnpm demo`: resets the demo folder `~/Rufi-demo` to the golden data set (`apps/server/tests/fixtures/golden.ts`) and opens the Rufi app on it, for trying Rufi by hand. It keeps only the folder's sign-in (`chatgpt.json`), and refuses another `RUFI_HOME`, a folder it didn't make (exact `demo.json` mark), a link at the folder or among its own files, and a running Rufi. The golden chat is written by Rufi's own transcript and tools; the screens' tests and the smoke set take the family from the same file.
- `pnpm rufi signin | status | signout`: Sign in with ChatGPT from the terminal. Needs `RUFI_HOME` set to a fictional data folder; tokens go to the macOS Keychain, never to files or logs.
- `pnpm rufi restore <backup> <new folder>`: restores a backup into a new or empty folder (no `RUFI_HOME` needed); the core makes the backups (`core/store/backup.ts`).
- `pnpm rufi ask "question"`: asks Codex (the pinned `@openai/codex`, never one on PATH) in a new thread using that sign-in, streaming the answer; nothing is saved in Rufi's chat. Ctrl-C stops it. Codex runs from `$RUFI_HOME/codex` and works in `$RUFI_HOME/workspace`, with full access (`PLAN.md` §4). Rufi's choices on top of Codex's defaults are all in `apps/server/src/agent/codex/settings.ts`; none of the user's own Codex setup or personal skills is loaded. `--debug` prints the log lines that go to `$RUFI_HOME/logs/rufi.log`.
- Rufi's tools live in `apps/server/src/core/tools/` (an Effect Schema each, no agent types); the agent gets them as `rufi.<tool>`. The person a tool reads is chosen by Rufi (`--person`, or the only one), never by the model. `pnpm tools:json` regenerates `tools.json`; a test fails if it differs.
- Test data: `cat apps/server/src/core/store/schema.sql apps/server/tests/fixtures/fictional-family.sql | sqlite3 "$RUFI_HOME/rufi.sqlite"` in a test folder. The core creates `rufi.sqlite` from `schema.sql` when there is none, and refuses one made by another schema (reset until dogfood).
- Models: `models.json` in the data folder is the allowlist (default: the strongest models); the core filters Codex's `model/list` through it.
- Queries use Kysely (`store.query`). `pnpm db:types` regenerates `tables.ts` from `schema.sql`; a test fails if they differ.
- `pnpm codex:types`: regenerates `apps/server/src/agent/codex/protocol/` from the pinned Codex after changing the pin; a test fails if they differ.
