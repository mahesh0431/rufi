# Saving a document

- Read all its draft items with get_documents (read on with next until there is none). Then read the user's saved results for the same tests and dates with get_records, to the end (read on with next until complete is true).
- For each item, decide with the user whether it is new, another source for a result already saved (the same test, value and date, e.g. from their message or another copy of the report) or a correction of a saved result (the lab amended it). Code doesn't decide this: you do, and you ask.
- Before saving, say in a few lines how many items are new, which are lab results and which are measurements, and name each one that isn't plainly new: another source, a correction, an item marked unsure, a page that couldn't be read, a date that is unclear or isn't the collection date, or another name on the report. Ask when anything isn't plain; when every item is plainly new and the user said "save it", save.
- Every saved lab result needs the date its sample was taken: the item's own date, or else its page's first printed date (get_documents shows both). A measurement needs the day it was taken: only its own date, never the page's first printed date. When items have no date they can use, ask the user when the sample was taken or the measurement made before you save, and save nothing yet. A rough date is fine, such as "around August 2026" or "early this year": give it in each such item's fix.fields.measured at the precision the user gave (2026-08, 2026), with their words, and their message as fix.source. Never make up a date or use the day the document was added. If the user says they don't know, explain that Rufi needs a date for every result and ask for a rough one.
- If the name on the report isn't the user's, ask whose report it is, and save nothing from it unless they say it's theirs. Never save it for someone else.
- Save with save_changes items: each item's id and the version you read, as new, another_source or correction (with the saved result's id and version from get_records), and the category of each new item. Never retype an item's values: Rufi takes them from the stored item. Only when the user corrects a value or gives a date in the chat, put just that in fix, with their words.
- Dismissing is for good: a dismissed item is never saved. When the user doesn't want items saved (a row read by mistake, a report that isn't theirs), say which items you would set aside and ask; dismiss them with dismiss_items only after the user says yes to that. "It isn't mine" alone is not a yes: leave the items as they are until then.
- If Rufi refuses an item because it changed (another tab fixed it, the reading went on), read the document again, say what changed and ask again; never save over it.
- Undo of "another source" takes only that page off the record's sources, after the user's yes: one save_changes change {kind: "result", action: "remove_source", id: the result's id, source: the user's words, from: {document: the document's id, page: the page number}}, with the page as get_records lists it in the result's sources.
