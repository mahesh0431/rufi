# 0031 · Timing is local times and a calendar rule, owned by each kind

**Date:** 1 Nov 2026 · **Status:** accepted

**Amended 2 Nov 2026:** a paired iPhone rings a person's reminders from a plan the Mac works out with this module for calendar days in the iPhone's own calendar, each dose a local date-time with no time zone, so a time rings at that time where the phone is. Where reminders ring is the person's choice (iPhone, Mac or both), and a notice may name the medicines when they chose Which ones.

A medicine keeps its **directions** as printed or said ("1-0-1 after food × 5 days"), and beside them the timing Rufi can use, in four values on `medicine_uses`: `times`, the local times of day (a JSON array of `"HH:MM"`, sorted, each once); `days`, an RFC 5545 rule for the days only (none: every day); its start (`started`) and `until`, the last dose, both in Rufi's date shapes at the precision said. Rufi AI turns the directions into timing with the person and saves it after their yes; code never reads the directions. `schedule` became `directions` (migration 30), in history too, so an old change's reverse still saves.

- **Each kind owns its timing.** There is no generic schedules table: a follow-up's rough month, a medicine course and a weekly job mean different things, each with its own table and its own notice marker. Recurring follow-ups, routines and Rufi's own scheduled work can take the same shape later.
- **One module works out doses** (`core/timing/doses.ts`): each day the rule gives × each time is a dose, from the start (a time from that time, a day, month or year from its first moment) to `until` (a time includes that time; a day, month or year all of it). Its questions are bounded: the doses on a day (Today), the latest dose in `(from, now]` (the notice claim), whether a dose falls after a day (Today's states).
- **rrule.js gives the days, and only the days.** `rrule` 2.8.1 (pinned) is given UTC midnights of local calendar days and read back as UTC year, month and day; it never sees a clock time. Rufi joins each day with each time as a local date-time, as follow-ups do. It takes only `FREQ=DAILY`, `WEEKLY` (with `BYDAY`) or `MONTHLY` (with `BYMONTHDAY`), with `INTERVAL`, and a date-only `DTSTART`; a rule outside these, or one that doesn't parse, gives no doses and shows as saved. rrule.js 2.8 reads `DTSTART;VALUE=DATE:` as no start at all (it then counts from now), so the adapter gives it `DTSTART:` with the same date. Its `toText` gives a rule's plain words when it can say them fully.
- **A pattern's start comes only from the saved rule.** Every other day, every few weeks or monthly with no day named depend on the day they began: Rufi AI puts it in `DTSTART`, and asks when it doesn't know (the `medicines` skill); there is no code refusal. A rule with no `DTSTART` counts from one fixed day (1 Jan 2000), which gives the same days for the forms that don't depend on a start. The day a question asks about is never a start, so Today, the claim and a restart agree.
- **Reminders are a field** (`remind`, off by default), changed by a save like any other, with a receipt and undo. After a change is merged with the stored row, reminders on need times: that, and the shape of a time, are the only checks.
- **The record never changes by itself.** A course's reminders stop after `until`; its status stays until the person says, and Rufi AI asks when it next reads the medicines.
- **Notices: only the latest dose, within 60 minutes**, never a backlog (ADR 0012, amended).

Considered: our own `{every, unit, weekdays}` JSON (reinvents RFC 5545, no calendar export later); full FHIR Timing (a large surface Rufi doesn't need); times inside the rule (`BYHOUR` × `BYMINUTE` multiply: 08:00 and 21:30 would give four times). The cost: the Mac's clock decides, so a time zone change keeps 08:00 local, and a daylight-saving gap moves that night's dose with JavaScript's local dates.
