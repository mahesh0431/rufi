# 0001 · Codex on the ChatGPT plan route

**Date:** 1 Oct 2026 · **Status:** accepted · **Pin:** `@openai/codex` 0.159.2

## Decision

Rufi runs `codex app-server` over stdio with OpenAI's documented provider settings for ChatGPT plan use (`openai_chatgpt_plan`, `env_key = "ACCESS_TOKEN"`, Responses over HTTP), and the access token from Rufi's own Sign in with ChatGPT. Codex keeps its standard behaviour; Rufi's few choices on top are in `apps/server/src/agent/codex/settings.ts`, each with its reason, and are checked on every start.

- **Rufi's own `CODEX_HOME`** (`$RUFI_HOME/codex`), so nothing from the user's `~/.codex` loads.
- **The app-server process gets its own `HOME`** (`$RUFI_HOME/codex/home`), so Codex doesn't find personal skills in `~/.agents/skills`, which no Codex setting controls in this version. The agent's commands get the real `HOME` back through `shell_environment_policy.set`.
- **Off:** plugins and apps (catalogs Rufi doesn't use; connectors need native Codex sign-in), and the background daemon (Rufi owns app-server's lifetime).
- **Stop:** `turn/interrupt`, then `thread/backgroundTerminals/clean`, because an interrupted turn leaves its commands running by design; then Rufi waits until `thread/backgroundTerminals/list` is empty, because the reply to clean only means it was queued. The list, not the process table: Codex keeps helpers such as `codex-code-mode-host` in their own process groups, and the list has no process ids in this version. If any step fails or takes too long, Rufi ends app-server and every process group under it. The turn returns only after Stop has finished.
- **Crash:** Rufi notes the process groups under app-server while a turn runs, and ends them if app-server exits on its own.
- **Token renewal:** a new access token means a new app-server and `thread/resume`, as OpenAI documents.
- **Rufi's tools** go to `thread/start` as `dynamicTools` in one namespace, `rufi` (experimental API). Codex keeps them with the thread and restores them on resume; they can't be changed afterwards. Rufi checks `modelProvider/capabilities/read` for `namespaceTools`, because without it Codex drops namespaced tools silently. Codex never times out a tool call, so Rufi answers within 20 s, and always with a result: Codex turns a JSON-RPC error into a bare "dynamic tool request failed".

## Consequences

- A thread's tool set is fixed when it starts, so M2 stores a fingerprint of the tool set with each conversation's thread and starts a new thread (reseeded from Rufi's transcript) when it changes.
- Research that needs the web goes through a chosen MCP server (Research, M5) or visible shell fetches, not Codex's web search, until the route supports it.
- Each pin bump: regenerate the protocol types (`pnpm codex:types`), rerun the contract tests, and recheck the `HOME` split and web search here.
