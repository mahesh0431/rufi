# 0032 · Paired apps reach Rufi through the remote door

**Date:** 2 Nov 2026 · **Status:** accepted

Rufi on the iPhone is a small Swift app around Rufi's own screens, served by the Mac. Later clients (a CLI, an MCP server, an agent harness) may reach Rufi the same way. The screens' listener answers only `127.0.0.1` from Rufi's own page, and must stay that way.

**A paired app has its own key, for one person, for good.** Pairing gives an app 32 random bytes (base64url), shown once; the record keeps only the key's SHA-256 (`paired_apps`). Whoever holds the key acts as that person and only that person: the person comes only from the app's row, never from what a request says. Revoking (unpairing on either side, or a restore) is final: a revoked app never matches its key again, and the phone pairs again. A device source that a paired app sends belongs to it through a `(person_id, paired_app_id)` key, so it can't be another person's.

**The remote door is a second listener**, on `127.0.0.1` at a port of its own, kept in the data folder's settings. Tailscale Serve gives it an HTTPS name on the tailnet (`https://<mac>.<tailnet>.ts.net:<port>`) and passes requests to it; never Funnel, and nothing listens on another interface. It runs only while an app is paired or a pairing code is live, and Serve's route is removed when neither is true. Rufi runs the Tailscale Mac app's own `tailscale` first, then the command on the PATH, each command with a 5-second deadline; Rufi never changes Tailscale's other settings.

**The same protections, its own checks.** Both listeners share the error answers, the headers (the CSP first), and the body limits (`server/http.ts`), and the person's routes (`server/person-routes.ts`). The door puts its own checks between them: the Mac's tailnet name with its port as Host (else 403), an Origin, when sent, of that name only, then who is asking. Each route is in one class: public (the screens' files, holding no health data), a pairing code, a launch token, a key, or a key or the app's session. Everything else is 404: every Mac-wide route, and another person's route. A launch and a session belong to one app; unpairing ends them, and its open streams, at once.

**Pairing shows a code on the Mac.** Settings › iPhone runs the Tailscale steps (this Mac's name and HTTPS, the door, Serve, then a request to the door through Serve that must reach it) and only then shows the code, as a QR code and the same link. The code lives in memory: single use, used up before anything is awaited, 10 minutes, one at a time. The app posts it with its name and gets its key, its person and the data folder's id (made at the first pairing; a restored copy keeps it).

The reason: one key per app for one person makes the person the boundary for every client, with nothing built only for the phone; a second listener lets the door differ only where it must, leaving the screens' listener as it is. The cost: Tailscale on both devices, its HTTPS turned on, and the Mac awake; a lost phone keeps what it already showed until it next reaches the Mac; and every new person route is reachable by paired apps once it is added, so each one must check that what it touches is the person's in the path.
