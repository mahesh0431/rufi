# 0028 · A reply's trend is drawn by Rufi from the AI's block

**Date:** 1 Nov 2026 · **Status:** accepted

One result's values over time show in a reply as a trend that Rufi draws: the AI writes a short block in its reply, in OpenUI Lang (an `openui-lang` fence naming `Trend` and its `Point`s), and the screens draw it with the record page's trend and a table of every value under it. Mahesh asked for charts as HTML, not pictures, with OpenUI; other charts and richer pages stay the AI's own pages (ADR 0017), and a picture is what the AI makes when the person asks for one.

**The language and renderer are OpenUI's; the components are Rufi's.** `@openuidev/lang-core` and `@openuidev/react-lang` (MIT, pinned at 1.0.2) parse the block, also half-written, and render it with Rufi's components: `Trend` and `Point` (`@rufi/contracts/visuals`), drawn by `apps/web/src/visual.tsx` with `trend.tsx`. The AI learns them from `visuals.md` beside the analysis skill, which `pnpm visuals:md` writes from the same components (a test checks the committed copy), so the instructions can't drift from what the screens draw. The prompt has no inline or edit mode: those tell the model to answer a change with only the changed statements, and each Rufi block is drawn on its own, so a changed trend is a new, whole block. Zod's eval probe is turned off before OpenUI loads (`@rufi/contracts/jitless`), so Rufi's strict CSP refuses nothing.

**A value as the record keeps it.** A point gives its date at its precision (or its words, or nothing), its value as printed, the number the record keeps for it and its flag and range as printed; code never parses the value. So a "<5" kept as 5 draws at 5, labelled "<5", as on the record page, and a value with no number, or with no calendar date (its words, such as "2026 (date unclear)", or nothing), is in the table, marked Not drawn. The screens order points by date, so the AI's order can't reverse time; the range at the top right is the newest drawn value's, as on the record page.

**Only a whole block draws once the reply ended.** While the reply is written, the trend draws what has come. Once it ended, the block draws only when OpenUI's own parse of it is whole (nothing cut off, every name used defined and every name defined used, and no errors) and it is what the components say: a Trend whose points are all Points, each prop by its schema, with null as left out and nothing coerced. OpenUI drops an undefined point without an error, and its parse doesn't check the root's component, which component sits in a point's place, or a number inside a prop that may be null; so without these checks a block could hide a value from both the trend and the table. Otherwise the reply shows the block's text and "This trend couldn't be drawn." The table shows every value plainly; no code compares them with the record.

**Display only.** The components have no actions, and the renderer gets no tools, so nothing in a block can call Rufi, fetch or run; every string is text. A `Query` the AI writes anyway fetches nothing: on its own beside the trend it is ignored, and in a value's place the block isn't a Trend of Points, so it shows as text. Nothing the AI wrote runs, and there's no frame.

**The first contract is frozen.** A reply keeps its block as the AI wrote it (stored as it came, and in backups with the chat, unlike a page in the AI's folder), and a block's props are positional. So `Trend` and `Point` keep their names, the order of their props and their meanings; a new prop goes only at the end, with a default; a change that would alter what an old block means gets a new component name, and the old one stays. The browser test's block is a stored first-version block, kept as written through upgrades. A stored block that no longer draws shows its text.

**Considered:** OpenUI's own component kit (its line chart spaces dates evenly and draws a missing value at 0, it injects styles Rufi's CSP refuses, and it isn't Rufi's look); OpenUI's browser bundle in a locked frame (a frame per trend again); the AI's own HTML page for every chart (a file and a frame each, nothing streams, no shared look); a JSON block of Rufi's own (Rufi would write the streaming parser, prompt and error reports OpenUI has); MCP Apps (UI a tool's author wrote, for hosts Rufi already is). **Not now:** trends in visit briefs, more components, interactivity, and charts drawn from saved records by reference rather than the values the AI writes.

**Install.** `@openuidev/lang-core`'s install script only sends install telemetry; it is listed in `allowBuilds` as never run. Its runtime telemetry is opt-in and never sent from a browser.
