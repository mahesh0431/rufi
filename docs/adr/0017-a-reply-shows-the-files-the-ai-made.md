# 0017 · A reply shows the files the AI made, in locked frames

**Date:** 14 Oct 2026 · **Status:** accepted

The AI works in its folder (ADR 0016): its programs draw charts, and it can make an HTML page of results to show a doctor. A reply must show these without letting what the AI made reach Rufi, the record or the network. Three trust levels stay apart: the reply's Markdown (sanitized, no HTML, no remote pictures), a page that runs script with no way to Rufi, and nothing the AI made that can call Rufi's tools or API.

**Files from two places, found again on every request.** A reply keeps the path as the AI wrote it; nothing is copied. Rufi shows a file only from the AI's folder (`ai/`, where a relative path starts) and from Codex's generated-image folder (`codex/generated_images/`), never the rest of Codex's home. `server/files.ts` resolves the path as the disk does (links followed) and refuses anything outside those roots, anything that isn't a regular file, and types other than PNG, JPEG, GIF, WebP and HTML (no SVG, which is a document of its own when opened). So a reply shows the file as it is now: a changed file changes an old reply, and a file that is gone keeps its card with "This file is no longer in the AI's folder." Rejected for now: a frozen copy of each file (a copy store, for a case the person can see and fix).

**Who may fetch: a short-lived address for one file.** The screens ask `GET /api/files?path=` (behind both session proofs) and get `/files/<token>/<name>`, a random token that names one file for 10 minutes. The file route takes only such a token, checks the file again, and answers with `nosniff`, `no-store`, `Cross-Origin-Resource-Policy: same-origin` and no CORS. No launcher secret, tab proof or MCP key is ever in an address. Rejected: the session cookie on the file route (a frame's or picture's load can't carry the tab proof, and the cookie alone would go with a load from a page on another port of this Mac, which the browser counts as the same site), a blob the page fetched (a blob frame takes the page's origin and policy).

**A page runs under its own policy, in place of Rufi's.** An HTML file's response carries one policy, not Rufi's as well (two policies would both apply): `sandbox allow-scripts` (an opaque origin, framed or opened on its own), inline scripts, styles and data pictures only, `connect-src 'none'`, `form-action 'none'`, `base-uri 'none'`, and Rufi's exact loopback origin as the only frame ancestor. So a page is self-contained: the AI may use the internet while it makes a page, but an opened page loads nothing remote and sends nothing out, works offline, and an old reply's page doesn't change because a library online did. The screens open it in a frame with `sandbox="allow-scripts"` too, after asking for a fresh address (a frame can't say its page didn't load). Rufi's own policy changes only in `frame-src`, which allows `/files/` and the diagram frame from Rufi's origin. Not promised: an absolute network air gap (a scripted document can still navigate itself); the help says "self-contained" and "can't load or send", which the browser test proves.

**Mermaid draws in a frame of its own.** Mermaid lays a diagram out with inline styles, which Rufi's `style-src 'self'` refuses, and Rufi's policy stays strict. So a `mermaid` block in a finished reply draws in `/diagram.html`, a sandboxed frame whose policy allows inline styles and runs only Rufi's diagram script (built as one plain script with a content hash: a module script from an opaque origin would need CORS). The screens pass the source and the theme's colours in the frame's address after `#` (never sent to the server); the frame answers with its height, or that it couldn't draw. The diagram's own settings can't change the theme, styles or HTML labels (Mermaid's `secure` keys). Until it is drawn, while the reply is written, and when it can't be drawn, the block shows as its code. Rejected: an SVG drawn in Rufi's page (unstyled, and every inline style a CSP refusal), `style-src 'unsafe-inline'` for Rufi's page.

**A generated picture is its own line.** Codex's image generation saves a PNG and reports an `imageGeneration` item with its path. Rufi keeps it as an activity of kind `picture` (migration 6), its path whole in `detail` and its bytes left out of `details`, and shows it as a picture, "Made by the AI", even when the reply doesn't link it; when a reply of the same turn shows that path, it shows there only.

**The Rufi app.** A popup still goes to the browser only while the page has no frame, but Rufi's locked frames (`/files/` and `/diagram.html`, opaque origins whose policies forbid popups) don't count, so a web link in a reply still opens while a diagram shows.

**Accepted race (TODO: check later).** A file removed between the address and the frame's load shows a readable page that says the file is gone.
