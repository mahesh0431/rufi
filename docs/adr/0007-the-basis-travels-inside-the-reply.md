# 0007 · An answer's basis travels inside the reply; Used is built from the reply's activity

**Date:** 8 Oct 2026 · **Status:** accepted

The AI ends every answer except small talk with a fenced code block tagged `rufi-basis` holding How: its own words on where the answer comes from and how it got there. The reply is stored as it came, as one transcript entry. When it is read, one rule on the Markdown tree (`core/chat/basis.ts`) takes every block tagged exactly `rufi-basis` out of the answer, wherever it is, and the last one is How. The rule runs on the stored text, before any display repair. A reply that hasn't completed shows no How, and also loses a last line that may be a fence it was cut in (such as "```rufi-ba"), so no half block shows while it streams or after a Stop. Used is never stored: each time a reply is shown, Rufi builds it from that reply's own saved activity, its calls to Rufi's tools as Rufi recorded them (`tool_calls`, exact on any agent) and its other activity lines, so two replies never share it. A new thread gets completed replies as they came, block included, so it learns the convention by example; a reply that didn't finish goes as its answer only, marked so. Considered: a final-answer tool taking the answer and How (atomic, but the answer no longer streams, Stop loses the partial answer, and a plain-text fallback is needed anyway); a separate tool for How alone (How and answer can part); the block first (breaks emergency advice first). The reason: the answer streams as before, Stop keeps what was written, any agent that returns text carries it, and code reads a declared structure, never the AI's words. The cost: code can't make the AI write How; live tests count it, and a forgotten or mistagged block means no How (a mistagged one shows as a code block).
