# 0010 · The reader runs on GPT-6.1-Sol, with Codex's exec in its pinned set of tools

**Date:** 11 Oct 2026 · **Status:** accepted

Documents are read with GPT-6.1-Sol at Medium effort by default; GPT-5.5 stays as the other choice in Settings, and a stored choice of either is kept. On the pinned Codex every GPT-6.x model is code-mode only: the model gets Rufi's tools only inside Codex's `exec` tool, which runs JavaScript in a V8 isolate with no Node, no file system and no network, and Codex always adds `exec`, `wait` and `request_user_input_async` beside it and `clock__curr_time` inside it, with no setting to turn them off. So the runner (`agent/codex/subagent.ts`) names each model's route (`SUB_AGENT_MODELS`): direct for gpt-5.5, code for gpt-6.1-sol, and the thread settings stay the same for both (plus Codex's sleep tool off). The allowed set on the code route is pinned exactly: at the top `exec`, `wait` and `request_user_input_async`; inside `exec` only `rufi__get_page`, `rufi__save_page` and `clock__curr_time`. `subagent.test.ts` proves this set on the real pinned Codex in every request, also after a forced compaction, and that a page image reaches the model through `exec` (the script passes the page's data URL to `image()`); a test that adds a tool, a namespace, sub-agents or the sleep tool goes red. At run time a call through `exec` is allowed only on the code route; on the direct route it still fails the turn, and a question to the user (`request_user_input_async`, shown as an agent message with questions) fails the turn on either route, because the reader has nobody to answer: the attempt's entries make no drafts, as for any other failed turn. The reason: the person chose Sol for reading quality, and accepted these extras; none of them reaches files, commands, the network, other agents or the record, and the reader's two tools are still bound by code to one person, document and attempt. The cost: the reader's contract is wider than two tools and depends on a pinned Codex detail (the `exec-` call ids and the exposed set), so a Codex upgrade must pass `subagent.test.ts` again; an image reaches the model only when its script shows it, which the reader pack measures, not code. Considered: a custom model catalog or a Codex fork to remove the extras (more upkeep, with no evidence it reads better); staying on GPT-5.5 only (the person chose Sol for reading).
