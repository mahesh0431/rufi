# 0024 · The agent system keeps its own database

**Date:** 30 Oct 2026 · **Status:** accepted

The agent system (`packages/agents`) runs every agent: Rufi AI's chat and the sub-agents it starts. It is its own package so it can become its own project, and it keeps what it runs in its own SQLite file, `agents.sqlite` in the data folder: the agents, their turns and steps (Rufi AI's too), one queue for every agent's inputs, the agent tools' receipts, and an event log. It knows no people, documents or health; Rufi maps its chats to agents. Rufi's database keeps what the person asked and what the AI answered, the receipts of saves and the record, so losing `agents.sqlite` loses the steps and the sub-agents, never a message, an answer or a save.

**Every change writes its event in the same transaction.** A change is one synchronous `node:sqlite` transaction (ADR 0003), so nothing else in the process runs between its writes; a change that records no event is refused. Event numbers count up and are never used again in the file (`AUTOINCREMENT`), even after a forget deletes an agent's events. The file has a **generation**, a random id made with it. Rufi keeps its place in the log as (generation, number) and applies each event in one transaction of its own; a file with another generation is a new one, and Rufi starts over from its own history. Rufi's own changes that the agents must act on are saved in Rufi first and sent by a stable id, so sending one again does nothing.

**It isn't backed up, exported or moved.** A backup and the export hold only `rufi.sqlite` and the originals (ADR 0008); a move leaves the file behind, with `codex/` (ADR 0014), whose conversations it names. After a restore or a move, Rufi starts it afresh, as when it's lost. It upgrades by its own migrations (`src/migrations/`, numbered from 1, the version in `PRAGMA user_version`), all pending ones in one transaction at open; a file from a newer Rufi is left unchanged and not opened.

Considered: the agent tables in `rufi.sqlite` (one transaction for both sides, but the package couldn't stand alone, and every backup would carry long logs of steps); rebuilding state from the events, as T3 Code does (a second way to be right; the tables are the state, and the log is how Rufi hears of it). The cost: two databases must be kept in step, through events one way and Rufi's saved intents the other; a crash between them is repaired at start, in an order the agent system's plan sets.
