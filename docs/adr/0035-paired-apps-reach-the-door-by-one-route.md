# 0035 · Paired apps reach the remote door by one route of three

**Date:** 12 Nov 2026 · **Status:** accepted · amends [0032](0032-paired-apps-reach-rufi-through-the-remote-door.md)

ADR 0032 gave the remote door one way in: Tailscale Serve, on the tailnet only, never Funnel. Tailscale needs a VPN on the phone, and many phones can't or may not run one (a work iPhone, for one). So the door gets a **route**, chosen in Settings › iPhone: **Tailscale** (Serve, the start), **Tailscale Funnel**, or **Cloudflare Tunnel** (the last comes in its own change). Whether the door is public is the person's choice; Settings says once, plainly, that a public route is public.

**A route is a small seam** (`server/remote-route.ts`): `up` at a pairing gives the door's Host and sets the route up, `resume` at a start brings back what doesn't outlive Rufi, `down` when nothing needs the door removes only what `up` set, `close` at quit ends what can't outlive Rufi. The record's `remote.route` names the route in use. Everything 0032 says of the door stays: the exact Host and Origin, the routes' classes, keys for one person, a code that works once. The door's own check moves out of Tailscale: after `up`, it POSTs a code that can't work to `https://<host>` and only Rufi's own 410 passes; while what answers isn't Rufi (no connection yet, a route's own error page), it asks again every 2 seconds, up to 30.

**One route at a time, changed only while nothing is paired** and no code is live or being used, on the server. A phone keeps the address it paired at, so changing the route means pairing again. Each route keeps its address while anything uses the door, so pairing a second phone never moves the first.

**Funnel's port is Rufi's own.** Funnel listens only on 443, 8443 and 10000, and shares one configuration with Serve, the latest command on a port winning. Rufi reads `tailscale funnel status --json`, takes the first of 8443, 10000, 443 that nothing holds (a command in the foreground too), saves it in `remote.funnel`, and reuses it for every pairing and after restarts. It moves only when no app is paired; with one paired and its port taken by something else, Rufi says so instead. `down` turns off that port only while it is still Rufi's own. HTTPS ends on the Mac: Tailscale's relay passes the traffic without reading it.

The reason: people whose phones can't run a VPN can use Rufi on them, with nothing built for one route only, and the door's protections unchanged. The cost: on a public route anyone on the internet can reach the door's address and its public files (Rufi's screens, no health data); only a live code or a paired app's key opens anything else. Rejected: two routes at once (each phone would need to know both, and the door two Hosts); a bulk unpair when the route changes (the person unpairs, which they see).
