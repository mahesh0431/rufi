# 0004 · Rufi keeps the conversation; the agent keeps its working state

**Date:** 4 Oct 2026 · **Status:** accepted

Each conversation's transcript is Rufi's own, in `rufi.sqlite`, stored before anyone is shown it: the user's messages (steers marked), one activity line for each thing the AI did (its kind, a short title, one short detail, done, failed or stopped, and when), the AI's replies, saved as they grow, with the model and how each reply ended, and a receipt entry for each save to the record, written in the save's own transaction (docs/adr/0005). Since M2.3 the transcript also keeps, with the conversation, everything the agent gave about each activity (what it sent and got back, as the agent's own JSON, replaced when the activity ends), the AI's reasoning summaries (Rufi asks Codex for them), and Rufi's own record of each call to its tools with exactly the answer the AI got (`tool_calls`); none of these is shown yet, except as an answer's Used (docs/adr/0007). Streaming chunks and the agent's sub-agent work are not saved; the agent keeps them in its own thread while that thread lives. The agent's thread is only a pointer: Rufi starts a new one when the model, the agent or Rufi's tools change, or when a thread can't be resumed, and gives it the last 10 messages with a note (a reply that didn't finish goes as its answer only, marked so); the `read_conversation` tool pages back through the rest. Messages sent during a reply wait in the agent's own queue (Codex `thread/queue/*`), not in a Rufi queue: Rufi saves each message when the agent starts it, by the id Rufi gave it, and after a crash fills a missing one from the agent's thread, never running it again. Stop pauses that queue; the next Send starts it again, oldest first. Before the agent has a message, Rufi's only copy is the conversation's draft: a send holds it (state `sending`, with the message's id) in one short commit before it asks the agent, so no save or other send can change it, and it is emptied when the agent took the message or returned to edit when the agent refused it. If Rufi stops meanwhile, it looks for that id in the transcript when it starts: found, the draft is emptied; not found, the text stays as `unknown` and the person is told to check the conversation. It is never sent again by itself: this is the one delivery state Rufi keeps, not a queue. The reason: a conversation survives a change of agent or model, and Rufi stores nothing it can't show or explain. The cost: a new thread knows only the last 10 messages until the AI reads further, and what waits lives in the agent's files. Saving sub-agent work, and how long the full activity is kept, are still open.

**8 Oct 2026, M2.5: one chat.** Each person has exactly one chat, made with them in the same transaction, and never a second (`chats.person_id` is unique), so two tabs never make two; there is no list, name, choice or per-chat address, and the user changes the subject by saying so. The transcript, turns, saves, drafts and waiting messages keep their links to it, and whose data it is doesn't change. The screens read the transcript by pages, not whole: a page is a range of `seq`, widened down to whole turns, with every entry in the range (also one of no turn) and the turns with no entry that started in its time, so pages never skip or repeat; older pages are read by a `seq` cursor, a newer read of an entry or turn always wins, and a reconnect replaces what is loaded with the latest page. Where the AI started afresh is worked out when the chat is shown, not stored: each turn keeps the agent thread it ran on, written with the turn, and a turn on another thread than the one before shows a quiet line; a compaction the agent completed is stored as its own activity and shows the same line. `read_conversation` is now `read_chat`. The schema was reset, with no migration: a backup from before is refused as from an older Rufi. The reason: one helper, one chat, and a chat of months must still open fast. The costs, accepted: a crash between a new thread and its first message loses the last-messages note (the AI can still read the chat), and a compaction finished while Rufi was down shows no line.
