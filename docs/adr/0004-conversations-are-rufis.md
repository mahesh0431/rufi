# 0004 · Rufi keeps the conversation; the agent keeps its working state

**Date:** 4 Oct 2026 · **Status:** accepted

Each conversation's transcript is Rufi's own, in `rufi.sqlite`, stored before anyone is shown it: the user's messages (steers marked), one activity line for each thing the AI did (its kind, a short title, one short detail, done, failed or stopped, and when) and the AI's replies, saved as they grow, with the model and how each reply ended. Tool outputs, reasoning, streaming chunks and the agent's sub-agent work are not saved; the agent keeps them in its own thread while that thread lives. The agent's thread is only a pointer: Rufi starts a new one when the model, the agent or Rufi's tools change, or when a thread can't be resumed, and gives it the last 10 messages with a note; the `read_conversation` tool pages back through the rest. Messages sent during a reply wait in the agent's own queue (Codex `thread/queue/*`), not in a Rufi queue: Rufi saves each message when the agent starts it, by the id Rufi gave it, and after a crash fills a missing one from the agent's thread, never running it again. Stop pauses that queue; the next Send starts it again, oldest first. The reason: a conversation survives a change of agent or model, and Rufi stores nothing it can't show or explain. The cost: a new thread knows only the last 10 messages until the AI reads further, and what waits lives in the agent's files. Saving outputs, reasoning and sub-agent work is decided with the reply structure in M2.3.
