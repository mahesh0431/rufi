# 0005 · The record changes only by a save the user agreed to in the chat

**Date:** 5 Oct 2026 · **Status:** accepted

The record changes in one way only: the AI's `save_changes` call in Rufi's own chat, after it said in plain Markdown what it would save and the user said yes. There are no cards, buttons or forms for now. Only Rufi's chat can save: the tool runs only with the chat's conversation, and a call from anywhere else (`rufi ask`, an MCP host later) is refused. The AI decides what the user meant (a "yes", a "no", "yes but explain first", "undo that", a late "yes" after the record changed); live AI tests check it. Code keeps only what must never go wrong, and keeps it deterministic: one save is one SQLite transaction that writes the `operations` row, each changed record, each record's whole row before and after (`record_changes`) and the receipt line in the transcript (an entry of kind `receipt` with the operation's id), or nothing. The receipt is written from the rows as stored, never from the AI's text. A save is keyed by the conversation and the agent's call id: the same call again returns the same receipt, and the same id with other changes is refused. Each change names the user's own words as its source; Rufi finds them in a message or steer of this conversation and refuses otherwise. A date carries the user's words, which must be in that message, and a date that must have happened (onset, measured, done care…) can't be later than that message, in the Mac's time zone. Records are never deleted (`removed` = 1); undo is a new save of the reverse, built by the AI from `get_overview`'s latest saves. The health rules that code can decide are in `core/record`: a prescription never makes a medicine use; a result read from a document changes only by amendment; "no known allergies" is never current beside an allergy that isn't inactive; any problem refuses the whole save with each problem named. Races are accepted, not prevented: a save that commits after Stop or a tool deadline keeps its receipt line, and the AI sees it next turn. The reason: Rufi trusts the AI with judgement and designs how it shows data later, so the only thing Rufi shows by itself is a receipt the user can check against what the AI said. The cost: an AI that misreads a "yes" can save the wrong thing; the receipt makes it visible at once and an undo fixes it.
