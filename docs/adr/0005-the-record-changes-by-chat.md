# 0005 · The record changes only by a save the user agreed to in the chat

**Date:** 5 Oct 2026, documents' draft items and typed sources added 10 Oct 2026, a result's category 11 Oct 2026, sources by message and dates as warnings 14 Oct 2026, an item saved again after an undo 17 Oct 2026, no date warnings or report guesses 24 Oct 2026, visits, `from`, `link` and `ref` 24 Oct 2026 · **Status:** accepted

The record changes in one way only: the AI's `save_changes` call in Rufi's own chat, after it said in plain Markdown what it would save and the user said yes. There are no cards, buttons or forms for now. Only Rufi's chat can save: the tool runs only with the chat's conversation, and a call from anywhere else (`rufi ask`, an MCP host later) is refused. The AI decides what the user meant (a "yes", a "no", "yes but explain first", "undo that", a late "yes" after the record changed); live AI tests check it. Code keeps only what must never go wrong, and keeps it deterministic: one save is one SQLite transaction that writes the `operations` row, each changed record, each record's whole row before and after (`record_changes`) and the receipt in the transcript (an entry of kind `receipt` with the operation's id), or nothing. The receipt is written from the rows as stored, never from the AI's text. A save is keyed by the conversation and the agent's call id: the same call again returns the same receipt, and the same id with other changes is refused. Each change rests on a message of the user's, found by where it is, never by its words: the message with the facts, so a source tells the person why the record is there. The AI names an earlier message by its position in the chat (`read_chat`) when the facts came before the yes; with none named, it is the user's newest message or steer in the turn the call is in. Which message carries the facts is the AI's judgement; code doesn't check it. Rufi resolves a position only within this person's chat and only to a message or steer, and refuses anything else; it stores the message's id, and the record's sources show that message's text. A steer sent a moment before the save may not be stored yet; the default then takes the turn's earlier message, which is the person's words too (an accepted race). A date carries the words it came from, as the user or a document said them, and Rufi compares them with nothing: the AI judges what the person meant, in any language. A date is saved as given, also one in the future that should have happened (an onset, a done visit): the AI mentions it so the person can decide, as its skill says; code doesn't judge which dates are late. Records are never deleted (`removed` = 1); undo is a new save of the reverse, built by the AI from `get_overview`'s latest saves. The health rules that code can decide are in `core/record`: a prescription never makes a medicine use; a result read from a document is never changed in place, only removed, restored or replaced by an amended result, except its category (ADR 0013); "no known allergies" is never current beside an allergy that isn't inactive; any problem refuses the whole save with each problem named. Races are accepted, not prevented: a save that commits after Stop or a tool deadline keeps its receipt, and the AI sees it next turn. The reason: Rufi trusts the AI with judgement and designs how it shows data later, so the only thing Rufi shows by itself is a receipt the user can check against what the AI said. The cost: an AI that misreads a "yes" can save the wrong thing; the receipt makes it visible at once and an undo fixes it.

A save can also take a document's draft items (`items`: each item's id, the version the AI read, and `as` new, another source of a saved result, or a correction that replaces one, with that result's id and version). The AI decides which, with the user; code takes each item's values from the stored item, never from the AI, and only a value the user corrected in the chat comes in `fix`, with their words. The one exception is the number of a value the person fixed on the document's page: the page keeps their value as typed, with no number, and the AI gives its number (`value_number`, `comparator`) when it saves the item, as it reads their value, asking when it is unclear; code takes it only for such an item. A value corrected in the chat (`fix`) replaces it, and takes only the number and comparator given with that fix. A result's date is the item's own (a measurement's too, ADR 0013); with none, the save is refused until the user gives one. A draft's report is its document (ADR 0019): its results share one report, never matched with another document's. Sources are typed rows (`record_sources`): the user's message, or a document's page; a record can have several, and "another source" adds only a row (Undo takes it off with `remove_source`), so a duplicate never becomes a second result. The chat's chips are pointers the box sends; the core checks each against the person and stamps its current version when it accepts the message (a document's rises with a reading or a fix, not a dismissal), and a save is refused when anything a message of the turn referenced has moved since. An item already saved returns its earlier save, while its page is still a source of a result that isn't removed (17 Oct 2026: after an undo took the page off, or removed the result, the item can be saved again, as an ordinary item save); a dismissed item (`dismiss_items`) is refused, and a Rufi event's turn can't save or dismiss. There is no count limit: a whole report saves in one transaction, and the receipt starts with a summary and folds its list. The reason: the duplicates and corrections are judgement, so they are the AI's with the user; what code keeps is that the values saved are the ones read, each from its page, all or nothing, once. The cost: a big save is one long transaction, and the AI sees a shortened receipt (the chat has it whole).

**24 Oct 2026: code stops second-guessing dates and drafts.** Gone: the warning for a date later than its message (and its stored copy, `operations.warnings`, migration 13), the parsing of a fix typed on the document's page into a number, an older draft's date taken from its page's first printed date, and an older draft's report matched across documents by its printed lab, number and date (and the report stored for it, `draft_items.report`, migration 13). They were code judging what the person or the AI meant. The AI mentions a future date after saving it, reads the number of a fixed value, and asks for a date an item lacks. The cost, accepted: a fixed value saved without the AI's number has no point on a trend, and an older draft's results land in a report of their own document; nobody has older drafts yet.

**24 Oct 2026: visits, and sources a change names.** A change can name the pages and Visits it rests on (`from`), add sources to a record whose values stay (`action: "link"`, undone with `remove_source`), and name a record it adds (`ref`) so a later change in the same save can cite it (ADR 0021). A change with `from` rests on no message unless the AI gives `source`: the person's yes is never a source. "A prescription never makes a medicine use" becomes "a Visit never makes a record by itself": each record from it is its own change.

**25 Oct 2026: device data isn't the record.** What devices measure comes in without a chat, into its own tables, with no save, receipt or undo; only how long values are kept deletes it (ADR 0023).
