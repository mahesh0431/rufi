# 0027 · Rufi's agents run on Claude too, through the Claude Agent SDK

**Date:** 31 Oct 2026 · **Status:** accepted

Rufi AI and the sub-agents it starts can run on Claude as well as on Codex: an agent runs on the provider of its model. The person ticks Claude's models in **Settings** › **Models** like Codex's (the shortlist), and chooses one in the chat's menu; Rufi AI can start a sub-agent on one, or move one below it there between its turns (ADR 0026). A chat keeps its model's provider with the choice, so after a restart it stays on that provider even when the provider lists no models then (Claude signed out), and nothing goes to another one.

**Claude is the one installed on the Mac, driven through the Claude Agent SDK.** Rufi looks for `claude` on PATH, then in the installers' usual places, when it first needs it, and refuses one older than 2.1.314. The SDK is pinned exactly (0.3.312), without its bundled Claude binaries. Each conversation is one Claude process under Rufi's settings, never the person's own: no CLAUDE.md, skills, plugins, connectors or MCP servers of theirs, Rufi's skills as its plugin, in `claude-plugin/` in the data folder (outside `claude/`, which the AI may never read, so it reads a skill's files), and Rufi AI's lock-down (ADR 0016). Claude signs in by itself in its own folder in the data folder, `claude/` (`CLAUDE_CONFIG_DIR`), and keeps there the conversations it has for Rufi (ADR 0001, ADR 0014). Rufi never reads or stores its sign-in. Signed out, Claude lists no models, and a message for a chat on one of its models stays in the box with Claude's line.

**A switch of provider starts afresh there.** An agent moved to the other provider opens a new conversation there at its next turn and never resumes the old one: Rufi AI's hears the chat's last messages, a sub-agent's its own last 10 turns. Rufi's ledger keeps every conversation a chat's agents had, on either provider.

**Considered:** calling Anthropic's API directly (Rufi would build the agent: its tools, sandbox, compaction and resume, which Claude Code has); Claude's print mode in the terminal (no control channel to steer, stop, ask its models or give Rufi's tools); shipping Claude with Rufi, and an API-key setting (later). **The reason:** the person's own Claude subscription, with the agent Claude Code already is, driven the way Rufi drives Codex. **The cost:** Claude isn't pinned and updates itself, so `pnpm claude:live` runs every case on the installed Claude to notice a change; listing the models asks Claude each time; nothing forgets a chat's Claude conversations yet, so they stay in `claude/` until Claude removes them (after 30 unused days) or the data folder goes.

**31 Oct 2026: Claude stays open between turns, and its thinking streams (T3 Code's way).** An agent's Claude process no longer closes when a turn ends: it waits for the next, and closes after 30 minutes with nothing to do (T3 Code's time), on Stop, when a turn finds Claude signed out, and when Rufi quits. This saves starting Claude, about 0.35 s, on each turn and each done message that wakes Rufi AI. What runs between turns is only what Claude itself keeps; Stop still interrupts Claude and ends its process and everything under it. Rufi also asks for Claude's partial messages and its thinking in summary, so its thinking shows as it is written; what is kept is the block Claude finished, which replaces the parts. Its answer and tool calls still show as each completes, as in T3 Code. Considered: streaming the answer's text too (more adapter work, with the same rules).
